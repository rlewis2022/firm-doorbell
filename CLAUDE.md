# Instructions for the AI (FIRM mold) — firm-doorbell

You are a **tool** used by the Engineer. You hold no role and you're never the one accountable: Ron
(Product Owner, Architect, Verifier, Integrator) is. This file is protected (A-09): you never edit it.

## What this repo is
A two-unit ESP32-S3 doorbell built as a worked example of the FIRM method:
- **Doorbell:** battery-powered, outside, button + speaker. Deep sleep; wakes on the button (GPIO2).
- **Indoor Ringer:** USB-powered, inside, louder. (Never call it a "chime".)
- They talk over **ESP-NOW**. Only the Indoor Ringer talks to the backend (Node.js, later).
- Records live in `docs/firm/` — read `05-decide.md` (architecture, absolutes, budgets, backlog) and
  `03-decision-log.md` before changing anything.

## How you work here
- You work **one increment at a time**, from its increment card. Do only what the card asks.
  No unrequested improvements, refactors, renames or "while I'm here" changes.
- The card's acceptance checks are **already written and locked** before you start. Make them pass by
  changing product code, never by changing the checks.
- **If a check, absolute or budget seems wrong: stop and say so.** Don't work around it. Changing a wall

- Prefer the smallest change that passes. Explain anything you weren't sure about.
- End each iteration with a short summary for the run log: files changed, checks you ran, open doubts.

## The absolutes (each is checked by the gate)
| # | Rule | Why |
|---|---|---|
| A-01 | No secrets in the repo: no Wi-Fi credentials, passwords, keys or tokens. | The repo is public. |
| A-02 | Logic (`firmware/*/src/logic/`, `firmware/common/logic/`) includes only C/C++ standard headers and other logic files. Never `Arduino.h`, ESP-IDF, FreeRTOS, drivers, or `src/hw/`. | Logic must compile and be tested on a PC; hardware stays easy to change. |
| A-03 | The Doorbell never joins or creates a Wi-Fi network and holds no credentials. Starting the radio in station mode for ESP-NOW (`WiFi.mode(WIFI_STA)`) is allowed. | Battery life; no secrets on an outdoor device. |
| A-04 | Neither unit plays a sound file it hasn't verified as complete and intact. On any failure it plays the **built-in sound** — never an older custom sound. | The built-in sound tells the user the new sound didn't arrive. |
| A-05 | Ringing never waits on the network, backend, radio link or a file transfer. **Sound starts first.** Ring-path code lives in `src/logic/ring/` and never includes link/transfer/network code. | It must ring with the network down. |
| A-06 | The built-in sound is a `const` array in flash, generated by `tools/wav2header.py` from a WAV in `sounds/`. Never computed at runtime, never hand-edited. | Computing it cost 237–316 ms per wake. |
| A-07 | Every message between separately updated parts carries a contract version (major.minor) and fails safe on mismatch. | The two units won't always run the same firmware. |
| A-08 | Add no library, tool or package. Approved, pinned dependencies are in `checks/approved_dependencies.json`. Audio uses the core's own `ESP_I2S` `playWAV()`. | Every dependency is code someone must maintain. |
| A-09 | Never change protected files: `CLAUDE.md`, `.github/workflows/*`, `checks/**`, `tools/*.py`, `firmware/*/sketch.yaml`, `tests/local/*` (and `locked/`, `third_party/`), `tests/sim/*`, `tests/real/*`. | A check you can change isn't a wall. |

## Budgets (checked)
- **B-01** Doorbell firmware ≤ 1,572,864 bytes (No-OTA layout). Warning at 80%.
- **B-02** Sounds: PCM WAV, 24 kHz, 16-bit, mono, ≤ 3.0 s (≤ 144,044 bytes).
- **B-03** Press-to-sound ≤ 300 ms (Real tier, RT-01; approved, DL-025). **B-04** Doorbell average current ≤ 0.9 mA (Real tier).

## Layout and layers
- `firmware/<unit>/<unit>.ino` — wiring only: create hardware objects, hand them to logic. No decisions.
- `firmware/<unit>/src/logic/` — decisions in plain C++ (tested on a PC). `logic/ring/` = the ring path.
- `firmware/<unit>/src/hw/` — thin wrappers over ESP32 APIs (I2S, sleep, ESP-NOW, storage). No decisions.
- `firmware/<unit>/src/sounds/` — generated headers only. `firmware/common/` — shared, versioned contracts.
- `tests/local/` — PC tests (doctest). Put any helper tests you write in `tests/local/unlocked/`.
- `spikes/` — archived experiments. Read for context; never copy their code into the product.

## Hardware facts (measured — Discover D1, spike S-01)
ESP32-S3 SuperMini, 4 MB flash, 2 MB QSPI PSRAM, 240 MHz, Arduino ESP32 core 3.3.12.
MAX98357A: BCLK=GPIO4, LRC=GPIO5, DIN=GPIO6. Button GPIO2 → GND (internal pull-up, ext0 wake).
Avoid pins 0, 3, 45, 46 (strapping), 19/20 (USB), 48 (LED), 43/44 (serial).
